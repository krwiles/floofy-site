The fourth fix PR from the [2026-10-02 full-repo review](2026-10-02-full-repo-review.md), covering `M1`–`M3` and the
Python half of `C7`, plus the leftovers PR 2's review deferred here. Every decision below was settled with the owner in
two grilling rounds on 2026-10-07.

**Branch:** `refactor/lambda-tidy-up`, off `working`, PR back into `working`.

**This is a refactor.** Visitors and the inbox see nothing new: every reply and every email (subject, recipients,
`reply_to`, HTML and text) stays byte-for-byte the same. The only intended change is that email-failure logs become one
consistent event.

## New shared modules (`aws_lambda/shared/`)

- **`email_sender.py`:** gains `send(...)` (decision 2). It sets the API key, builds the params with `email_content()`, adds
  `reply_to` if given, calls `resend.Emails.send`, and on any exception logs `email_failed` with the context and returns
  `False`.
- **`form_input.py` (new):** `invalid_fields(request, max_lengths, required) -> bool`. True if a required field is
  blank or any text is over its limit.
- **`limits.py`:**
  - gains a `FormLimits` frozen dataclass and `check_visitor(cur, limits, ip)`;
  - holds one fixed per-visitor count query per table (like `GLOBAL_CAP_QUERIES`, picked by name, never from input);
  - keeps `busy_reply`, so `rate_limited` and `busy` replies come from one module.
- **`dates.py` (new):** `format_sgt(when)` gives the "Wednesday, 30 September 2026 at 12:00 PM (SGT)" text used in every
  email and the admin page.

## Per-Lambda changes

Every form Lambda follows the same order:

1. log the request;
2. read the body into its dataclass;
3. refuse invalid input;
4. `check_visitor`;
5. save;
6. email with `send`;
7. reply.

| `floof-comm`    | `handle_post`; `COMMISSION_LIMITS`; `invalid_fields` plus its email, type and usage rules; `check_visitor`. Both emails use `send`, and its local `send_email` goes. Owner then customer, as decided in PR 1.                  |

## Risks and assumptions

- **Snapshot fragility:** snapshots catch _any_ difference, including harmless whitespace in the email HTML. That's the
  point here; after this PR they're only regenerated deliberately.
- **Fixing the clock:** each Lambda reads "now" a little differently (`datetime.now(...)` in comm and contact,
  `created_at` from the row in api, and `time.time()` for admin-link expiry). The snapshot test patches each source; if
  one is missed, the test fails loudly rather than passing by accident.
- **Log rename:** any saved CloudWatch query filtering on `owner_email_failed` needs updating. The docs list the new
  name.

## Changes made during the build

- **`send()`'s first parameter is `recipients`,** not `to`, so the `to="owner"` / `to="customer"` log label can use the
  agreed name.
- **`FormLimits` checks its table name when it's created,** and each table's per-visitor query is written out in full.
  The SQL-safety test refuses queries built with string formatting, even from a fixed list.
- **`floof-api` now reads its body with `str(...)`,** like the other two Lambdas. A crafted request sending a number as
  the author used to crash into a 500; it's now treated as text. Normal submissions are unaffected (the snapshots
  match).
- **The snapshot tests also cover `floof-admin`'s four confirm and done pages,** since its `ACTIONS` table refactors
  them.

## Changes made after review

- **Missing or `null` fields count as empty in every form Lambda** (a shared `text_field()`), never as the text "None".
  Before, `floof-api` crashed into a 500 on `null` and the other two stored "None". Anything else (a number, say) is
  read as text.
- **`floof-api` now reads `RESEND_API_KEY` like the others** (`os.environ.get`). A missing key still ends as
  `email_failed`, with the review saved; only the logged error text differs.
- **`check_visitor` treats a missing count row as zero.** `COUNT(*)` always returns a row, so this changes nothing in
  practice.
- **Decision 6 is partly done:** the `ACTIONS` table holds each action's lookup, title, delete-or-block choice and
  block-reason label, and the six `action ==` chains are gone. The consequence wording and the "already done" check
  stay as one `deletes` branch each, since a block's wording depends on the target's IP. A test keeps the table's keys
  equal to the actions `admin_links` can sign.
- **Step 8's "PR 2 plan leftovers":** the PR 2 plan never listed them (they were in its review), so there was nothing
  to mark.
