## Interface changes

| What                                                       | Before           | After                               |
| ---------------------------------------------------------- | ---------------- | ----------------------------------- |
| `floof-api` POST `ok`                                      | 201              | 200                                 |
| Exact-limit input (review, contact)                        | `400 invalid`    | accepted                            |
| Blank or whitespace-only required field (all form Lambdas) | accepted         | `400 invalid`                       |
| Commission price that rounds up to the maximum             | `500 error`      | `400 invalid`                       |
| Commission: owner email sent, customer email failed        | `500 error`      | `200 ok`, logged with `request_id`  |
| Commission: owner email failed                             | `500 error`      | unchanged                           |
| `floof-admin` unexpected crash                             | AWS's 502        | 500 HTML page with security headers |
| `createFormSubmission().action`                            | resolves at once | resolves when the reply arrives     |

The site reads only `code`, so 201 → 200 breaks nothing. **The database doesn't change**: no tables, columns or SQL.
Prices are stored rounded to cents, which the `numeric(10, 2)` column already did.

## Risks and assumptions

- **No AWS access:** the timeouts and the crash page are tested only with fakes.
- **Resend isn't pinned until PR 2 (`S5`):** `build.sh` installs the latest version, while tests run on 2.49. If a later
  version renames `RequestsClient` or `default_http_client`, importing `email_sender` breaks; the import-time test only
  catches that if the local venv is upgraded too.
- **Python versions:** tests run on 3.12 locally; AWS runs 3.14.
- **`B10` duplicates:** an owner-email failure tells the visitor `error`, and a retry saves a second row. Accepted.
- **`B3` rejections:** the `action` promise must never reject, or the global error listener reports it. Covered by
  the `try`/`catch` shape and a test.
- **Character counting:** the site counts an emoji as 2 characters and Python as 1, so the site can be stricter than
  the backend, never looser. Boundary tests use ASCII.
- **Diff size:** `reviews.ts` / `reviews.html` are touched by `B3`, `B5`, `B12` and `C6`; per-step commits keep it
  reviewable.
