# PR 2 plan — abuse protection

The second fix PR from the [2026-10-02 full-repo review](2026-10-02-full-repo-review.md), covering `S1`, `S2`, `S3`,
`S5` and `S6`. Every decision below was settled with the owner in four grilling rounds on 2026-10-07.

**Branch:** `fix/abuse-protection`, off `working`, PR back into `working`.

## Scope

**In:**

- **Customer email (`S1`):** a strict address check, links made unclickable in the customer's copy, and commission type
  and usage limited to their fixed lists.
- **Rate limits (`S2`):** a per-IP limit on the contact form, and a global daily cap on every form.
- **IPv6 matching (`S3`):** an IPv6 visitor is matched on their /64 network, for both limits and blocks.
- **Dependencies (`S5`):** pinned with hashes.
- **Hardening (`S6`):** `nosniff` on `floof-admin`, and a setup step to confirm Resend click tracking is off.

**Out:**

- **Turnstile:** deferred; revisit only if the caps are actually being hit.
- **AWS reserved concurrency:** skipped.
- **The site's CSP (`S4`):** PR 6.
- **Scrubbing error text in logs:** CloudWatch retention covers it.

## Decisions

| #   | Topic                   | Decision                                                                                                                                                                                                                                                  |
| --- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Customer address        | Exactly one plain address: at most 100 characters, one `@`, a dot in the domain, and no spaces or `<>,;"`. Anything else replies `invalid`.                                                                                                               |
| 2   | Customer copy           | Still repeats the full request, but every link-looking piece of the visitor's text is made unclickable (`https://evil.example` → `hxxps[:]//evil[.]example`).                                                                                             |
| 3   | Where links are defused | Only in the **customer's** copy, in every visitor-typed field (name, description, reference links, usage explanation, deadline, notes). The owner's copy keeps real links.                                                                                |
| 4   | Type and usage          | `commission_type` must be `chibi`, `emote` or `illustration`; `usage_type` must be `personal`, `promotion`, `distribution`, `products` or `unsure`. Anything else replies `invalid`. A test checks these against `pricing.json`.                          |
| 5   | IPv6                    | Matched on its /64, for rate limits **and** blocks. IPv4 stays per address. (The Lambda URLs are dual-stack: each has an AAAA record, so IPv6 visitors arrive as IPv6.)                                                                                   |
| 6   | Existing blocks         | Left as they are (there are none).                                                                                                                                                                                                                        |
| 7   | Contact storage         | A new `contact_messages` table with only `ip_address` and `created_at`, kept indefinitely (no clean-up).                                                                                                                                                  |
| 8   | Limits                  | Reviews 1 per IP per hour (unchanged); commissions 2 per IP per 24 h (unchanged); contact **3 per IP per 24 h** (new). Global caps per rolling 24 h: reviews **20**, commissions **10**, contact **20**.                                                  |
| 9   | Global cap reached      | Refused with a new reply code, **`busy`**, and logged as `global_cap_reached`. Each form gets its own message in both languages ("lots of requests right now, please try again tomorrow").                                                                |
| 10  | Dependencies            | Each Lambda gets a `requirements.in` listing only what it imports. `uv pip compile --generate-hashes` writes the hashed `requirements.txt`, and `build.sh` installs with hash checking. `requests` and `certifi` leave the lists; `resend` pulls them in. |
| 11  | Admin header            | `floof-admin` adds `X-Content-Type-Options: nosniff`.                                                                                                                                                                                                     |
| 12  | Resend click tracking   | A setup step for the owner to confirm it's off (if it were on, Resend would see the admin-link tokens).                                                                                                                                                   |

No ADR: each of these is a constant or a small rule that's easy to change.

## Database

**A new table**, created by an `aws-setup.md` step that is run **before** `floof-contact` is uploaded:

```sql
CREATE TABLE contact_messages (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  created_at  timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
  ip_address  inet        NOT NULL
);
CREATE INDEX idx_contact_messages_created ON contact_messages (created_at DESC);
```

**No other schema changes.** `inet` already holds both addresses and networks:

- A **block** on an IPv6 visitor stores their network (`2001:db8:1:2::/64`) in `blocked_ips.ip_address`.
- `reviews` and `commission_requests` keep storing the visitor's full address.

## Backend changes (`aws_lambda/`)

- **New `shared/ip_scope.py`:**
  - **`ip_scope(ip) -> str`:** the address itself for IPv4 (`203.0.113.7`), its /64 network for IPv6
    (`2001:db8:1:2::/64`). It uses `ipaddress.ip_network(f"{ip}/64", strict=False)`.
  - **Query use:**
    - rate limits: `ip_address <<= %s::inet`, meaning "this row's address is inside the visitor's scope";
    - blocks: `ip_address >>= %s::inet`, meaning "this block covers the visitor".
- **`shared/blocklist.py`:**
  - `is_blocked` uses `ip_address >>= %s::inet`, so a /64 block catches every address in it, and an old single-address
    row still matches.
  - `block` stores `ip_scope(ip)`.
- **New `shared/limits.py`:**
  - **`over_global_cap(cur, table, cap) -> bool`:** counts the table's rows from the last 24 hours. The table name comes
    from a fixed allowlist, never from input, and the query stays parameterised.
  - **`busy_reply()`:** replies `503 {"code": "busy"}` and logs `global_cap_reached`.
- **`floof-api`:**
  - The rate-limit count uses the scope.
  - The global cap (20) is checked after the per-IP limit.
- **`floof-comm`:**
  - **Checks:** the scope count, the global cap (10), the strict email check, and the type/usage allowlists, as
    `COMMISSION_TYPES` / `USAGE_TYPES` constants with a comment pointing to `pricing.json`.
  - **Customer copy:** goes through a new `defuse_links(text)` after escaping.
- **`floof-contact`, in order after validation:**
  1. Blocklist.
  2. Per-IP limit (3 / 24 h, counted in `contact_messages` by scope).
  3. Global cap (20).
  4. Insert the row and commit.
  5. Email.

  The insert comes before the email, so a failed send still counts against the limit.

- **`floof-admin`:**
  - Blocks store and describe the scope ("IP range 2001:db8:1:2::/64 will no longer be able to …").
  - The contact Block link still carries the IP as a number, and the block covers its scope.
  - `X-Content-Type-Options: nosniff` joins the security headers.
- **New `shared/email_rules.py`:**
  - **`is_plain_address(email)`:** the decision 1 check.
  - **`defuse_links(text)`:** `http(s)://` becomes `hxxp(s)[:]//`, and a dot between a word and a 2-or-more-letter
    word becomes `[.]`. It also catches bare domains like `evil.example` and addresses like `me@mail.com`. It may
    over-match ordinary text (`Mr.Smith`), which is accepted for the customer copy.
- **Dependencies:**
  - `floof-*/requirements.in` lists `psycopg[binary]==3.3.4`, plus `resend` for the three emailing Lambdas.
  - `requirements.txt` is generated with:

    ```
    uv pip compile requirements.in --generate-hashes --python-version 3.14 --python-platform x86_64-manylinux2014 -o requirements.txt
    ```

  - `build.sh` installs with `--require-hashes`.
  - The README and `CLAUDE.md` get the upgrade command.

## Steps

Each step is test-first; commit at each green step.

1. **`ip_scope`, then the blocklist** using it.
2. **`limits.py`** (global cap plus `busy`), then the scoped per-IP counts and caps in `floof-api`.
3. **`email_rules.py`**, then `floof-comm`: email check, allowlists, defused customer copy, scope and cap.
4. **`floof-contact`:** the per-IP limit, cap and insert.

   zips.
7. **Frontend:** `busy` (model, service, i18n keys, tests).
8. **Docs.**
9. **Final checks:** full pytest and `npm test`, `npm run build`, Prettier and the comment check.
10. **Review:** two-axis review, a follow-up commit, then ask the owner before pushing.

## Risks and assumptions

- **No AWS or database access:** the `inet` operators (`<<=`, `>>=`) and the new table are tested only through the SQL
  the fakes record. A typo in SQL would show up only after deploy, so the queries are kept short and spelled out in this
  plan.
- **Performance:** `<<=` / `>>=` can't use the existing b-tree indexes. With a few hundred rows that's microseconds, so
  no new index is added.
- **Caps can be used against you:** an attacker can use up a day's cap and make the form say "busy" to everyone. That's
  accepted; Turnstile is the answer if it ever happens.
- **Defusing over-matches** ordinary text with a dot between words in the customer copy. That's accepted.
- **Hashed requirements:** upgrading a package now means rerunning `uv pip compile`. The command is documented.
